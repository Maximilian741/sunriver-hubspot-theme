This guide walks through setting up SAML-based SSO between Okta and your SunRiver-managed environment. Total time: about 25 minutes if you have admin access to both sides.

Before you start

  • Okta admin access
  • SunRiver admin access (or someone who has it on standby)
  • The list of users you want to provision day-one
💡
Tip. Set up in a non-production tenant first if you have one. SAML config is fiddly and easier to iterate on without breaking anyone's login.

Step 1 — Create the Okta application

In Okta admin, go to Applications → Browse App Catalog and search for SunRiver. Pick the SAML 2.0 connector and click Add.

Step 2 — Configure SAML settings

Use these values:

  • Single sign-on URL: https://app.sunriverconsulting.com/sso/acs
  • Audience URI: urn:sunriver:saml
  • Name ID format: EmailAddress
  • Application username: Email

Step 3 — Map attributes

We require three attributes minimum: email, firstName, lastName. If you want group-based access, add a groups attribute filtering by your SunRiver-* group prefix.

⚠️
Heads-up. If your group names contain spaces or special characters, the regex filter in Okta needs escaping. We've seen this trip up about half of all setups.

Step 4 — Hand the metadata to SunRiver

Download the IdP metadata XML from Okta and paste the URL into your SunRiver admin SSO page. We'll validate it on save and tell you if anything's off.

Step 5 — Test before flipping

Assign yourself to the application in Okta, then sign in via the SSO link. If it works, assign the rest of the org. If it doesn't, see the troubleshooting section below.

Common issues

  • 'User not found' errors: usually a NameID mismatch. Check that the Okta user's email exactly matches the SunRiver user's email.
  • Loop on login: SAML response signature validation failing. Re-download the metadata.
  • Group access not working: attribute statement filter regex is off — check escaping.
